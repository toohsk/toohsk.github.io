Title: 凍結済み小型言語モデルを賢く・安くする：バイト完全KV状態グラフティング
Date: 2026-07-18
Category: AI/ML
Tags: SLM, AI, 論文解説
Summary: バイト完全なKVキャッシュグラフティングにより、勾配ゼロで凍結12Bモデルに検証済み知識を注入し、AIME 2025スコアを80%から93.3%に向上させながらトークン消費を6,574倍削減する新手法。

## なぜこの研究が重要か

LLMがクエリに答えるたびに、プロンプト内のすべてのトークンを最初から再計算している。同じ数学的証明、参照実装、ドメイン知識が数百万のクエリに埋め込まれている場合、それは数百万回再計算される — 静かに積み重なる巨大な無駄である。

この論文はその無駄を、一見シンプルな観察で攻略する：モデルがプロンプトを読む際に計算するKVキャッシュは、入力・重み・数値精度の**決定論的な関数**である。もしそのキャッシュ状態をビット完全にキャプチャし、ディスクに保存し、後から損失ゼロで別の推論コンテキストに復元できれば：

1. **一度計算された知識は二度と再計算不要**。12kトークンのプロンプトのプリフィル時間が1,547msから18msへ、**85.6倍高速化**。
2. **モデルが持っていない知識を、重みを一切変えることなく永続的に注入できる**。ファインチューニング不要。アダプター不要。検証済みのKVブロックをキャッシュするだけ。

この2つの特性が組み合わさり、著者らが「検証済み知識フライホイール」と呼ぶ仕組みになる：追加の推論努力で難問を解き、外部で解を検証し、バイト完全なKVアーティファクトとして凍結し、以降のクエリではグラフトするだけ。凍結されたGemma-4-12Bが**AIME 2025で80.0%から93.3%に向上**（31B版の公式スコア89.2%を超える）し、8つの繰り返し難問を401,026トークンではなく**61トークン**で解く。

これはプロンプトキャッシングでもRAGでもない。まったく新しいもの：モデルのアテンション状態への正確で永続的・ポータブルな、ゼロ勾配の知識注入である。

## 技術的なアプローチ

### Taliesin：バイト完全グラフトエンジン

中心的な主張は、KV状態が**ロスレスの忠実度**で復元できるというものだ。近似的にではなく、バイト単位で完全に。論文はこの正確性を厳密に定義している：

$$\text{SHA-256}\bigl(\text{bytes}(\ell_{\text{graft}})\bigr) = \text{SHA-256}\bigl(\text{bytes}(\ell_{\text{fresh}})\bigr)$$

ここで $\ell_{\text{fresh}}$ は新規フォワードパスからのロジットベクトル、$\ell_{\text{graft}}$ はキャッシュされたKV状態を復元後のロジットベクトル。これは以下を含意する：

$$D_{\text{KL}}(p_{\text{graft}} \,\|\, p_{\text{fresh}}) = 0 \qquad \text{かつ} \qquad \arg\max \ell_{\text{graft}} = \arg\max \ell_{\text{fresh}}$$

Gemma-4-12B（RTX 5090, Blackwell）での50サンプルにわたって、グラフトは中央値でも99パーセンタイルでもKL divergenceゼロ、argmax不一致ゼロ、全トライアルでSHA-256バイト等価を達成する。この保証はクロスコンテキスト（新しい推論プロセスへの復元）、クロスサーバー、主要なランタイムリファクタリング後も維持される。

### なぜ「自己位置」だけが唯一の正確な動作点なのか

Rotary Position Embedding（RoPE）は、キーベクトルを回転させることで位置をエンコードする：$\mathbf{k}_t \leftarrow R_t \mathbf{k}_t$。厳密な算術では、位置 $t$ と $s$ 間のアテンションは**相対角度** $t - s$ のみに依存する（加法定理による）：

$$\cos(a)\cos(b) + \sin(a)\sin(b) = \cos(a - b)$$

しかし**32ビット浮動小数点演算**では、この等式はビット完全には成立しない。同じトークンペアを異なる絶対角度 $(a, b)$ vs $(a+M, b+M)$ で表現すると、結果は約1ULP（最終桁の1単位）異なり、これがネットワーク層とロジットソフトキャップを通じて増幅され、約0.015のKL divergenceになる。

この帰結は明確だ：**自己位置グラフトが唯一のバイト完全な動作点**である。KVブロックを元の位置範囲 $[0, N)$ で復元することはバイト完全だが、オフセット $M$ に移動すると正確ではない — グラフトのエラーではなく、*新規計算*自体が既にオフセット $M$ でのものとオフセット $0$ でのものとで同量だけ異なっているからだ。これはモデルの特性であり、エンジンの問題ではない。

### Galahad：検証済み知識フライホイール

学習ループは意図的にシンプルだ：

1. **解く**：凍結モデルが失敗する難問に、追加の推論努力で取り組む
2. **検証**：外部の健全性チェックを適用（生成されたプログラムを実行し、既知の答えを出力することを確認）
3. **保存**：検証済み解のKV状態をディスク上の永続ブロックとしてキャプチャ。余分なアクセラレーターメモリはゼロ
4. **ルーティング**：新しいクエリを分類し、関連するブロックを選択
5. **グラフト**：バイト完全なブロックを復元。モデルは検証済み知識をプリフィルしたかのように読み込む — ロスレスで

論文は2つの検索レジームを区別する：
- **再発（Recurrence）**：全く同じ問題が再び来る。ブロックにルーティングし、グラフトし、保存された答えを返す。コスト：問題1つあたり約7.6トークン（50,000+ではなく）
- **転移（Transfer）**：構造的に類似しているが数値的に新しい問題が来る。グラフトされたメソッドコンテキストをワンショット例として使用し、凍結モデルが新データに適応する。これは記憶のテストではなく汎化のテスト

## 先行研究との比較

| 手法 | 永続性 | 正確性 | 勾配不要 | 追加メモリなし |
|---|---|---|---|---|
| ネイティブプロンプトキャッシュ | ❌ (セッション限定) | ✓ | ✓ | ✓ |
| RAG（トークン注入） | ✓ | ✓ | ✓ | ❌（毎回再読込） |
| ファインチューニング / LoRA | ✓ | N/A | ❌ | ❌ |
| KVキャッシュ共有（LMCache等） | ✓ | 近似 | ✓ | ✓ |
| **KV状態グラフティング（本論文）** | **✓** | **✓（バイト）** | **✓** | **✓** |

RAGは永続的だが、注入された知識を毎回トークンとして再読み込む — コストが繰り返される。ファインチューニングは永続的だが重みを変更し、学習実行コストが必要で、単一事実の粒度では合成不可能。本論文は推論時学習の基盤としてのバイト完全・永続・ポータブルなKV状態グラフトの最初の公開デモンストレーションだ。

## 実験結果の読み方

**AIME 2025ベンチマーク**（30題の数学コンペ問題、Gemmaの2025年1月プリトレーニングカットオフ後にリリース）：

| 設定 | スコア | トークン/問題 |
|---|---|---|
| 凍結12B ベース（pass@1） | 56.7% | ~3,300 |
| サンプリングと投票 | 76.7% | ~25,000 |
| コードルーティング（キャッシュなし） | 76.7% | ~4,100 |
| コードルーティング + グラフトライブラリ | **90.0%** | ~4,360 |
| 信頼度ゲート + ライブラリ | **93.3%** | — |

90.0%の実行は、キャッシュなしベースラインより約5.6%多いトークンで**13.3ポイントの精度向上** — キャッシュされた知識から買う能力は、追加サンプリングから買う能力より約**50倍安い**。

**再発のコスト削減**：ベースモデルが401,026トークン予算内で解けなかった8つの難問が、キャッシュされた検証済み解から61トークン合計で回答される — **6,574倍のトークン削減**、約3,000〜8,700倍のエネルギー削減。

**コンテキスト拡張**：2,854,766トークンのストアが88の永続ブロックとして構築される。ストア内のどのポイントも深さに関係なく一定のコスト（~0.29秒）で取得でき、追加アクセラレーターメモリはゼロ。設定された32kサービスウィンドウが32 GB GPUで87倍に拡張される。

## アルゴリズムの重要部分の解説

### バイト完全性の証明構造

論文は正確性を**対抗的な反証**によって証明している：7つの候補説明を各々テストして排除した：

1. 半精度の丸め誤差 — CPU決定論的ビルドで排除
2. スライディングウィンドウバッファリング — フルサイズKV有効化で排除
3. オフセット大きさ — オフセット{8, 128, 1024, 4096}での均一な残差で排除
4. デュアルロータリーパス — 明示的にテスト
5. RoPEシフトの周波数不一致 — 排除
6. 三角関数カーネルでの大角度引数簡約エラー — 排除
7. 物理スロット配置からの簡約ツリー再結合 — 排除

残るのは32ビット浮動小数点での余弦加法定理の非結合性 — 32ビットRoPEでは不可避で、モデル自体で測定可能で、グラフトとは完全に分離している。

この結果として導かれる重要な不等式は：

$$D_{\text{KL}}(\text{自己位置グラフト}) = 0 \qquad \text{vs.} \qquad D_{\text{KL}}(\text{新位置グラフト}) \approx D_{\text{KL}}(\text{0での新規計算 vs. Mでの新規計算})$$

つまりグラフトは位置残差に何も加えない — 残差はすべてモデル自身の位置感受性によるものだ。

### フライホイールループの収束保証

フライホイールが収束する理由は、ストアへの登録に**外部検証**が必要だからだ — システムは健全性チェックに合格した解のみを保存する。これによりエラー増幅を防ぐ：多くの自己改善ループとは異なり、Galahadは誤った知識を追加できない。

ルーティングも大規模化に対応して設計されている：各ブロックには1つの検証済み解が含まれ、ルーターは単一の関連ブロックのみを選択する（関連メソッドコンテキストと無関係なものが混在するとモデルが混乱することが判明したため、すべてのキャッシュ済み解のフラットなプレフィックスではない）。

### 数式の直感的理解

**KL divergence = 0 の意味**：グラフトされたモデルと新規計算の次トークン予測分布が**確率的に区別不可能**であること。つまり、グラフトはプレフィルを完全に置き換え、モデルはその知識をまるで今読んだばかりのように処理する。

**SHA-256等価テスト**：ロジットベクトル（語彙全体のスコア）のバイト表現のハッシュが一致する。数万の浮動小数点数の全ビットが一致するということ — 統計的なほぼ等価ではなく、完全な等価。

**プリフィルスピードアップ85.6倍**：12k-tokenの知識を新規に処理する代わりに、1トークンを前進させるだけ。すでに計算済みのKV状態を使うため。

## 限界と課題

- **バイト完全性はアーキテクチャ固有**：異なる浮動小数点蓄積を行う2つのGPUアーキテクチャは、同じグラフトからバイト同一の結果を生成しない可能性がある。保証はアーキテクチャ内で成立。
- **エンジンは独自仕様**：Taliesinグラフトメカニズムは入出力レベルのみで説明され、内部アーキテクチャは非公開。結果はコミットされたSHAハッシュで裏付けられるが、再現にはクローズドなベンチマークスイートが必要。
- **長いプログラムでの2つの失敗**：ライブラリ内で最長のキャッシュ済みプログラムを持つ問題#11と#14は、転移実行で解けなかった。失敗はキャッシュのバイト完全性ではなく、大量のコードコンテキストのモデルのワンショット再適応にある。
- **ロータリー位置制約**：自己位置での復元が唯一のバイト完全なレジーム。浮動小数点RoPEモデルでの任意オフセットグラフトは達成不可能。

## 今後の展望

**著者が示唆するFuture Work**：
- マルチブロック合成の完全な正確性達成（現在は機能的には正しいが残差あり）
- オープンウェイトモデルでの再現実装（Taliesinエンジンが独自仕様のため）
- クロスアーキテクチャポータビリティのためのハードウェア抽象化レイヤー

**この研究から派生する発展的な研究方向**：
- **圧縮KVストア**：2.85Mトークンのストアが40.6 GBのディスクを占有する。ロスレスKV圧縮（スパースアクティベーションや相関キーベクトルの活用）で大型ストアをコンシューマーハードウェアで実用的にできる。
- **位置非依存アーキテクチャへの拡張**：ALiBiや位置エンコーディングなしのアーキテクチャでは、RoPEの制約がなくなり、クロスオフセットの正確なグラフトが可能になる可能性がある。
- **自動フライホイールパイプライン**：現在、Galahadループは初期難問の人間によるキュレーションが必要。問題発見、多様な解生成、マルチ検証器コンセンサスの自動化で完全に自己改善するフライホイールが実現できる。
- **エージェント用スキルライブラリ**：464トークンのスキルマニュアル（160 MBのKV状態）のキャッシュデモは、より大規模なオンデバイスエージェントスキルライブラリへの道を示す。

## エッジ・オンデバイスへの示唆

この論文はエッジ・オンデバイス推論に直接関連する複数の意味を持つ：

**冗長な計算の排除**：オンデバイスモデルは通常、重複する知識コンテキスト（システムプロンプト、参照文書、スキルライブラリ）で繰り返し実行される。バイト完全なKVグラフティングにより、その繰り返しプリフィルをクエリごとの $O(n)$ トークンから $O(1)$ トークンに変換し、**バッテリー寿命を直接延長し、モバイルデバイスの熱スロットリングを削減**する。

**拡張知識のためのゼロメモリオーバーヘッド**：ゼロ追加アクセラレーターメモリでの87倍コンテキスト拡張は、DRAMとVRAMの両方が制約されるエッジハードウェアで特に価値がある。4 GBのオンデバイスモデルがディスクから数億トークンの検証済み知識ストアにアクセスでき、アクセスごとのディスク読み取り時間（~0.29秒）のみを支払う。

**エネルギー比例性**：再発問題での3,000〜8,700倍のエネルギー削減は、バッテリー駆動展開に直接的な意味を持つ。繰り返しの質問に再計算ではなくキャッシュされた検証済み解から答えるオンデバイスモデルは、知識集約型ワークロードでアクティブセッション時間を桁違いに延長できる。

**スキルキャッシングのオンデバイスエージェントへの応用**：論文では464トークンのスキルマニュアル（160 MBのKV状態）がキャッシュされ、バイト同一に復元できることを示し、モデルはキャッシュ状態のみを使って6つのタスクを正しいスキルにルーティングする — クエリ時にスキルからのコンテキストトークンなしで。これはオンデバイスアシスタントの低レイテンシーのパーソナライゼーションへの道を開く。
