Date: 2026-07-30
Category: AI/ML
Tags: SLM, AI, 論文解説
Summary: 70〜500Mパラメータ規模のSLMにおけるPPOの失敗原因を体系的に特定し、3層の安全機構で解決することで、オンデバイスLLMへの古典的RLHF適用を可能にした研究。

## なぜこの研究が重要か

RLHF（人間のフィードバックによる強化学習）における PPO（Proximal Policy Optimization）は、大規模言語モデルのアライメントの定番手法だ。しかし 70〜500M パラメータ規模——スマートフォンや組み込みデバイスで動作する SLM（Small Language Model）——においては、「PPO は不安定すぎて使えない」という通説があり、現場では SFT（教師ありファインチューニング）や DPO などの手法に逃げるのが通例だった。

問題は診断の透明性だ。報酬モデルをパイプラインから外すと、「なぜモデルが改善しているのか、していないのか」を示すスカラー信号が失われる。制約のあるハードウェアに展開するエージェントシステムでは、このフィードバックループは学習ツールであると同時にモニタリング手段でもある。

この論文は新しいオプティマイザを提案しない。代わりに「PPO が SLM スケールで実際に失敗する理由は何か、そしてその失敗は修正できるか？」という問いに答える。答えは「はい」——3つの具体的かつ再現可能なエンジニアリング修正によって、135M パラメータ程度のモデルでも古典的な PPO が機能するようになる。

## 技術的なアプローチ

### 3つの失敗モードと3つの修正

著者らは 15 の（モデル、コーパス）組み合わせを SFT → 報酬モデル → PPO の完全なパイプラインで学習し、すべてのハイパーパラメータを固定して実験を行う。この制御されたスイープによって、SLM スケール特有の 3 つの失敗モードが明らかになった。

**失敗モード I: LoRA 勾配フローのサイレントな遮断**

TRL（Transformer Reinforcement Learning）ライブラリで LoRA と PEFT を組み合わせると、アダプタパラメータが PPO 学習ループ中にサイレントに非学習可能とマークされる場合がある。モデルはロールアウトを生成して損失を計算するが、LoRA 重みへの勾配が流れないため、方策分布は変化しない。

修正は**マージ・再初期化法**：
1. SFT LoRA アダプタをベースモデルの重みにマージ
2. ゼロ初期化の新しい LoRA アダプタをアタッチ
3. マージ済み重みを学習可能な方策と冷凍参照方策 π_SFT の両方として使用

**失敗モード II: 重要度比計算における bfloat16 の数値オーバーフロー**

PPO の核心信号は重要度比だ：

$$\rho_t = \exp\!\bigl(\log\pi_\theta(a_t|s_t) - \log\pi_{\text{ref}}(a_t|s_t)\bigr)$$

方策と参照方策が近い確率を割り当てる場合（PPO 初期には頻繁に起きる）、2 つの対数確率は絶対値が大きく互いに近い値になる。bfloat16（仮数部 7 ビット）ではその差の精度が失われ——**桁落ち（catastrophic cancellation）**——重要度比が 10^6 を超えてハードウェア例外が発生する。

この問題は特に 200M パラメータ未満のモデルで顕著に現れる。浅いネットワークはより集中した確率分布を生成するため、桁落ち問題が悪化する。

修正はシンプル：**PPO ループのすべてのテンソルを float32 で演算する**。SFT と報酬モデルの学習は bfloat16 のままでよい。

**失敗モード III: 分布的崩壊**

長い裾を持つ報酬分布にクリッピングされていない KL ペナルティが組み合わさると、方策が参照モデルの確率がほぼゼロの領域に押しやられ、非整合な出力を生成するようになる。

修正は**3 層の安全機構**：
- 報酬のホワイトニング（バッチ内正規化 + 3σクリッピング）
- 重要度比しきい値ガード（ミニバッチの平均 ρ > 5 なら更新をスキップ）
- 重みロールバック（オプティマイザステップ前にスナップショットを保存、NaN/Inf 検出時に復元）

### キャパシティ・ヘッドルーム仮説

論文の理論的貢献として、**「SFT 事前分布が流暢（PPL < 20）かつ報酬信号が識別的である場合にのみ PPO は改善をもたらす」** というキャパシティ・ヘッドルーム仮説が提案される。

モデルのパラメータ数だけでは PPO の成功を予測できない。TinyStories で PPL = 7.0 の 135M SmolLM2 は成功し、CNN/DailyMail で PPL = 70.3 の 160M Pythia は失敗する。鍵となるのは SFT チェックポイントがすでに流暢なテキストを生成しているかどうか——RL が言語流暢性と同時に戦わずに済む「ヘッドルーム」が必要だということだ。

## 先行研究との比較

SLM スケールのアライメント研究は SFT または DPO/KTO/GRPO などの報酬モデルを排除した手法に偏っている。PPO の安定性に関する大規模での研究（InstructGPT、Llama 2 RLHF）は存在するが、500M 未満のスケールでの失敗メカニズムの体系的調査はこれが初めてだ。

公開されているインストラクション調整済みベースラインとの比較では、提案パイプラインは SmolLM2-Instruct や Qwen2.5-Instruct と同等の性能をわずか 10K サンプルで達成する——報酬信号が嗜好のギャップを正確に検出して改善を集中させるからだ。

## 実験結果の読み方

主要な結果：

- **Pythia-410M（TinyStories）**: Δ = +1.355、勝率 59.9%、95% CI [+0.61, +2.10]、p < 0.001
- **SmolLM2-360M（TinyStories）**: Δ = +0.724、勝率 59.7%、95% CI [+0.32, +1.13]、p < 0.001
- **SmolLM2-360M（Wikitext-103）**: Δ = +0.274、p < 0.05

3 つの設定で統計的に有意な改善が確認された。唯一の有意な回帰は Pythia-410M（Wikitext-103）の Δ = -1.043（p < 0.001）。この設定の SFT PPL = 25.4 は流暢性閾値 PPL < 20 を超えており、キャパシティ・ヘッドルーム仮説と一致する。

勝率は Φ(Δ / √(σ²_PPO + σ²_SFT)) として解析的に計算される。勝率 59.9% は、ヘッドトゥヘッドの比較で PPO モデルが SFT モデルより高いスコアの回答を生成する確率が約 60% であることを意味する。

## アルゴリズムの重要部分の解説

### PPO 目標関数の構造

$$J(\theta) = \mathbb{E}_{p \sim \mathcal{D},\, y \sim \pi_\theta(\cdot|p)}\!\bigl[r_\phi(p, y) - \beta\,\mathrm{KL}\!\bigl(\pi_\theta(\cdot|p)\,\|\,\pi_\text{SFT}(\cdot|p)\bigr)\bigr]$$

第一項は学習した報酬モデル r_φ の下で高スコアを獲得する報酬。第二項は SFT 事前分布からの逸脱にペナルティを与え、報酬ハッキング（報酬モデルを予期しない方法で最適化すること）を防ぐ。

KL 項には**逆方向（モード探索）KL**が使われる。これは新しい方策が SFT 事前確率の低い領域にマスを割り当てることにペナルティを与える。SLM スケールでは、β が小さすぎると崩壊が起き、大きすぎると学習が止まる——このバランスが SLM 特有の困難さだ。

### Bradley–Terry 報酬モデル

$$\mathcal{L}_\text{RM}(\phi) = -\mathbb{E}_{(p, y^w, y^l) \sim \mathcal{D}_\text{RM}}\!\bigl[\log \sigma\bigl(r_\phi(p, y^w) - r_\phi(p, y^l)\bigr)\bigr]$$

この損失はシンプルだが深い意味を持つ。σ はシグモイド関数で、スコア差をスコア yʷ が好まれる確率に変換する。重要なのは**加法的不変性**：すべてのスコアを定数 c だけシフトしても損失は変わらない。なぜなら差だけが重要だから。これが異なる設定間で絶対スコアを比較できない理由だ。

### マージ・再初期化アルゴリズムの意味

アルゴリズム 1 の核心的な洞察：SFT アダプタをベースモデルにマージした後、ゼロ初期化の新しい LoRA（BA = 0）を取り付ける。PPO の第 0 ステップでは新アダプタは何も加算しないので、方策は正確に π_SFT となる。冷凍参照方策も同じく π_SFT であるため、PPO 開始時の KL ペナルティはゼロから始まる。これは RLHF の数学的に正しい初期化であり、他のアプローチは学習開始時に「幻のKL」を導入してしまう。

## 限界と課題

- **シングルターン評価のみ**: 15 設定の研究は T=1（1 ターン MDP）を使用。マルチターンのエージェント的フレームワークはコードとして公開されているが、本論文では評価されていない
- **合成嗜好データ**: 嗜好ペアは人間の評価者ではなく劣化戦略（切り詰め、シャッフル、不一致）で生成
- **固定ハイパーパラメータ**: 失敗モード分析のためにすべての設定で意図的に固定。モデルごとのチューニングはより良い結果をもたらすが分析が難しくなる
- **2 つのアーキテクチャのみ**: Pythia（GPT-NeoX）と SmolLM2（Llama）のみ。他のアーキテクチャへの一般化は未検証

## 今後の展望

著者が示唆する方向：
- マルチターンエージェント的インタラクション（ツール呼び出し、多段対話）への拡張
- 合成劣化ではなく実際の品質判断に基づく報酬モデル

この研究から派生する発展的方向性：
- **選択的混合精度 PPO**: オーバーフローリスクが高い箇所だけ float32 を使用し、メモリを節約しつつ安定性を維持
- **PPO 中の適応的 LoRA ランク拡張**: マージ・再初期化トリックを応用してランクを動的に増加させる機構
- **蒸留ウォームスタートから PPO へ**: 教師モデルで SFT データを生成して流暢性閾値を確実に満たしてから RLHF を開始する

## エッジ・オンデバイスへの示唆

- **PPO は 500M 未満のモデルでも実用的**——3 つの修正を実装すれば。明示的な報酬信号を諦める必要はない
- **RLHF 開始前に SFT PPL を確認する**。PPL < 20 の閾値が実用的な go/no-go 基準。SFT モデルがまだ流暢性に苦しんでいるなら、RL は助けにならない
- **PPO テンソルには float32 を使う**。70〜500M モデルでは float32 vs bfloat16 のメモリコストは 140MB〜1GB の差——現代のエッジデバイスで十分管理可能
- **報酬モデルは監視手段でもある**。新しいユーザーやドメインに適応する必要があるオンデバイスエージェントには、方策とは独立してログ取得・デバッグ・更新できる明示的な報酬信号が有効
- 計算コストは **2× RTX A6000 で約 16 GPU 時間**——大学の研究室や小規模な AI チームでも実行可能
