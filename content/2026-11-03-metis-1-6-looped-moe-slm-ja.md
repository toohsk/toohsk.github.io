Title: Think Twice：Metis-1.6が示すループ型MoEアーキテクチャによる効率的な小規模言語モデルの可能性
Date: 2026-11-03
Category: AI/ML
Tags: SLM, AI, 論文解説
Summary: Metis-1.6は、ハイブリッドMamba-2/アテンションMoEスタックをトークンごとに2回実行するループ型アーキテクチャを採用した2つの小規模言語モデル（Praxis: 2.94B全体/0.46Bアクティブ、Logos: 10.23B全体/1.18Bアクティブ）で、わずか1.02Tトークンの学習で数学分野30モデル中2位のPareto最適効率を達成した。

## なぜこの研究が重要か

言語モデルを改善する支配的なパラダイムは単純だ。パラメータを増やし、データを増やす。フロンティアラボはパラメータ数をトロフィーのように発表する。しかしこのアプローチには天井がある。少なくとも費用の天井は、最大規模の組織しか押し上げられない。

Metis-1.6はそのパラダイムへの直接的な挑戦だ。Lernexの一人の研究者Giulianno Vollmerが、学習インフラ・トークナイザー・データパイプライン・評価ハーネスを含むすべてをAMD Instinct MI300Aアクセラレータ上でゼロから構築し、効率性対能力のPareto最前線に位置する結果を出した。

この問題が難しい理由は多次元にある：

1. **計算効率**: 単純にレイヤーを追加せずに、パラメータ当たり・トークン当たりの実効計算量を増やしたい
2. **データ効率**: 大規模ラボの10T+トークン予算なしで有能なモデルを学習する
3. **アーキテクチャの新規性**: 既存部品の組み合わせではなく、真に新しい設計で既存のdense/MoEベースラインを超えられるか

この論文はまた、珍しく率直なポストモーテムでもある。学習全体を通じて間違ったオプティマイザが動き続けたバグ、モデルが自ら無効化した1.77Bパラメータのメモリコンポーネント、5つのSFT失敗モード、そして正しい答えにペナルティを与える長さ報酬の符号反転バグが詳細に記述されている。

## 技術的なアプローチ

### ループ型アーキテクチャ

PraxisとLogosは、異なるスケールで同一のアーキテクチャパターンを使用する：ハイブリッドMamba-2/アテンションMoEスタックを**トークンごとに2回実行**し、2回のパス間で重みを共有する。

- **Logos**: 20層（アテンション3層：5、10、15層目；Mamba-2が17層）、d_model=2,560、10.23B全体 / 1.18Bアクティブ（両パス合計2.36B）
- **Praxis**: 12層（アテンション2層：4、8層目；Mamba-2が10層）、d_model=2,048、2.94B全体 / 0.46Bアクティブ

核心的なアイデア：モデルを幅広く・深くするのではなく、同じスタックが各トークンを2回処理する。これにより各トークンに「もう一度見直す」機会が与えられる。2回のパス間の情報伝達は**クロスパス深度メモリ**（4ヘッド、256次元、ゲートは-6で初期化してほぼゼロからスタート）で行われ、1回目のパスのメモを2回目に渡す。このメモリは小さく学習可能で、パスごとに別パラメータを必要としない。

効率性の根拠：Logosは10.23Bパラメータを保持しているが、両パス合計でトークンごとに活性化するのは2.36Bのみ。これは上位モデルの中で最も少ないアクティブパラメータ数だ。

### 潜在空間混合エキスパート（Latent MoE）

各レイヤーは1,024次元に圧縮された潜在空間で動作するMoEブロックで終わる：

```
FFN(x) = W_up(S(z) + Σ_{e ∈ TopK(r(x), 4)} g_hat_e(x) * E_e(z))
```

ここで`z = W_down * x`（潜在空間への射影）、`S`は常にアクティブな共有SwiGLUエキスパート、`E_e`はルーティングされるSwiGLUエキスパート（Logosでは幅768のものが192個、Praxisでは幅512のものが128個）でtop-4ルーティング。負荷分散は補助損失なしのバイアス更新（レート1e-3）とルーターz損失（係数1e-3）で行われる。ここがパラメータ効率の源泉だ。

### ハイブリッドMamba-2 + アテンション

Mamba-2レイヤーがシーケンス混合の大部分を担う（Logosで17/20、Praxisで10/12）。Mamba-2の主要パラメータ：拡張率2、状態サイズ128、ヘッドdim 64、幅4の因果畳み込み、チャンクサイズ256。KVキャッシュを保持するのはLogosで3層のみ（Praxisで2層）—これによりコンテキスト長が伸びてもメモリ増加が緩やかになる。アテンションは40クエリ/10KVヘッド（Praxisは32/8）、ヘッドdim 64、**位置エンコーディングは一切なし**。

Mamba-2レイヤーが再帰状態を通じて暗黙的な位置情報を提供するため、位置エンコーディングを完全に除去できる。4Kから131Kトークンへのコンテキスト拡張も、フルな再アーキテクチャではなく18Bトークンの継続学習フェーズで実現できた。

2回のパスで同じアテンション重みを使いながら異なる動作をさせるため、各アテンション層が**パスインデックス付きランク8低ランク更新**をQ/K/V射影に加える。このアダプテーション機構のパラメータコストは極めて小さい。

### 残差ストリームとハイパーコネクション

各サブレイヤーは標準トランスフォーマーの1本ではなく、**4本の残差ストリーム**から読み書きする。学習された4×4混合行列—8回のSinkhorn-Knoppイテレーションで二重確率行列に射影—がストリーム間の情報を統合する。64次元のパス埋め込みがコントローラに条件付けされ、1回目と2回目のパスで異なる動作をする。

### 学習設定

**データカリキュラム**（804.76Bトークン）：
- Phase A（68.9%）：広域フィルタリングWebテキスト、書籍、学術論文、コード
- Phase B（26.1%）：数学・科学・ソフトウェアエンジニアリング・構造化分析テキストを重み付け増加
- Phase C（5.0%）：厳選された技術文書、形式的証明、競技数学、リファレンスドキュメント

全シャードは評価ベンチマークに対して13-gramシングルマッチングで汚染除去済み。

**コンテキスト拡張**：163,840トークンまでの長文書上で追加18Bトークン。Logosのneedle-in-haystack精度は131Kトークンで19.53%から68.75%に向上、RULERは128Kで60.14%に到達。

**ポストトレーニング**：長い推論トレース（数学・科学・コード）上で120B SFT、次いで全領域（ツール呼び出し・指示追従を含む）で80B広域SFT。

## 実験結果の読み方

Pareto最前線というフレームワークが適切な視点だ。（学習トークン数、ベンチマーク平均スコア）の散布図で、Logosは影付きコーナーに位置する：中央値より高いスコアを、中央値より遥かに少ないデータで達成。アクティブパラメータ対スコアでも同様のパターン。

**ループ設計が勝つ領域**：数学と形式的推論。2パス構造はアーキテクチャ自体の連鎖的思考を提供する—1回目のパスが表現を構築し、2回目が深度メモリのメモを使って精緻化する。これが、多段階の記号的操作を要する数学オリンピアード問題に対して特に効果的な理由かもしれない。

**弱点**：コード生成（30モデル中17位）、指示追従（18位）、安全性（19位）、長文コンテキスト（think modeで24位）。これらは学習データ量と強く相関し、2.5T〜8Tトークンで学習されたモデルが既にLogosを上回る。弱点はアーキテクチャの問題ではなく、データの問題だ。

**Praxis（2.94B全体）**は同じベンチマークで平均36.62点。AIME 2025：27.08%、HMMT February 2026：24.24%、GSM8K：76.80%、HumanEval：62.80%。パス当たり0.46Bアクティブパラメータで、8ドメイン中4つでPareto最前線に位置する。

## アルゴリズムの重要部分の解説

### 長さ報酬の符号反転（命題1）

これが最も技術的に精密な発見で、注意深く理解する価値がある。

**設定**：同じプロンプトに対するG個のサンプルのグループで、正しくて短いサンプルは報酬1、正しくて長いサンプルは報酬`1-λ`、不正解は0。優位は GRPO スタイルのグループ平均中心化：`A_i = (r_i - r_bar) / σ`

**何が問題か**：グループ平均 `r_bar = p * [1 - λ(1-q)]`（p=正解率、q=正解サンプルのうち短いものの割合）。中央値分割（q=1/2）でλ=1/2の場合、長い正解サンプルの報酬は`1-λ = 0.5`。`p > 2/3`（16サンプル中11個以上が正解）になると、この報酬がグループ平均を下回り、優位が負になる。

**直観的なイメージ**：あるプロンプムが「簡単」になった時（多くのサンプルが通る）、詳しく考察した正解が「短い正解」より低く評価される。モデルは「しっかり考える」のではなく「手短に答える」ことを学ぶ。

```
A_i ← max(0, A_i)  # 正解サンプルに対して
```

これが1行の修正だ。短い正解への正のシグナルは保ちながら、長い正解への負のシグナルを除去し、不正解への負のシグナルは維持する。

### 潜在空間MoE FFN（式1）

```
FFN(x) = W_up(S(z) + Σ_{e ∈ TopK(r(x), 4)} g_hat_e(x) * E_e(z))
z = W_down * x  (1,024次元の潜在空間へ射影)
```

`W_down`でモデル幅（2,560）から潜在次元（1,024）に圧縮することが鍵だ。エキスパートが潜在空間で動作するため、各エキスパートの持つ重みは小さくなり、192個のエキスパートでも現実的なメモリに収まる。`W_up`で元の幅に戻す。この「圧縮してからルーティング」というパターンがLatentMoEの核心で、参照パラメータ数を大幅に削減しつつ表現力を維持する。

### n-gramゲート（式2）

```
g^{(ℓ,p)}_{t,s} = σ(<h_{t,s}, v_s> / √d_model + b_s)
h_tilde_{t,s} = h_{t,s} + g * m_t
```

残差ストリームの現在の状態`h`とゲートベクトル`v`の内積でゲート値を計算し、メモリ出力`m_t`の注入量を制御する。このゲートのバイアス`b_s`が学習によって大きく負の値になり、`σ(負の大きな値) ≈ 0`となってメモリが実質的に無効化された。モデルはn-gramメモリが持つノイズ（ハッシュ衝突）のコストがメリットを上回ると「判断」した。

### SFTの参照固定サンプリング目標（式3）

```
L(x, y*) = -1/|y*| * Σ_t clip((π_θ/π_ref)^0.25, 0.2, 2.5) * log π_θ
```

通常のクロスエントロピーは`-log π_θ`で、π_θが非常に小さい（低確率な）スタイリスティックトークンに対して勾配が無限大になりうる。この式は`(π_θ/π_ref)^0.25`という確率比で重み付けし、[0.2, 2.5]でクリップすることで、参照モデルとの大きな乖離を持つトークンの勾配を抑制する。0.25乗は比率を穏やかにし、クリップが作動する範囲を広げる役割を持つ。

## 限界と課題

論文は称賛に値するほど率直に認める：

1. **コードと指示追従が弱い**：これらドメインで30モデル中17〜18位。2.5T〜8Tトークンで学習されたモデルが既に上回る。ボトルネックはアーキテクチャではなくデータ量だ。
2. **think modeでの長文コンテキストが低性能**：128KでRULERがthink modeで34.17%（direct modeは60.14%）。アテンション層が少ないKVキャッシュの優位性が、非常に長い推論チェーンでは逆転する。
3. **事実再現が低い**：SimpleQA Verified：3.78—1/12のデータ量が直接の原因。
4. **結論はすべて間違ったオプティマイザに基づく**：MuonとAdaMuonの違いはクリーンに評価されていない。Metis-1.7のアブレーション（Section 10）が修正後の価値を測定しているが、Metis-1.6自体はアテンションでAdamWを全期間使用した。
5. **一人の研究者という制約**：大規模ラボより速くイテレーションできるが、計算量では競えない。Pareto効率の主張は本物だが、絶対能力の上限はフロンティアモデルより遥かに低い。

## 今後の展望

**著者が示唆するFuture Work（Metis-1.7とMoRE）**：
- **MoRE（Mixture of Recursive Experts）**：ループアーキテクチャが可変深度再帰に進化し、トークンを異なるパス回数にルーティング。論文には10Bトークンのアブレーション結果が含まれる。
- **オフアクセラレータの大規模n-gramメモリ**：500億パラメータのテーブルをアクセラレータ外の三値形式（1.85ビット/値、BitNet b1.58量子化）で保持し、HBMを圧迫せずにロングテールな事実を記憶する。
- **修正したオプティマイザ**：アテンション行列へのAdaMuonの正しい適用、Mambaの融合射影の適切な分離。

**この研究から派生しうる発展的な研究方向（独自考察）**：
- **推論時の適応的パス深度**：問題の難しさに応じて1〜3パスを適応的に選択することで、トークンごとの計算予算を最適化できる。困難なトークンには2パス、簡単なトークンには1パスというような動的深度モデルに発展しうる。
- **深度メモリのスケーリング**：クロスパス深度メモリ（4ヘッド、256次元）は極めて小さい。1回目のパスの状態をより長いバッファで保持したり、ヘッド数・次元を増やしたりすることで、2パス設計の推論利得を強化できる可能性がある。
- **Mamba-2/アテンション混在時の学習ダイナミクス**：オプティマイザ監査で、アテンション行列とMamba行列が同じ学習率スケジュールで大きく異なる動挙動を示すことが判明した。各モジュールの幾何学的特性に応じてオプティマイザを調整する（例：Muonの直交化を各サブコンポーネントに正確に適用）ことが最も明確な効率改善になりうる。
- **三値/量子化エキスパート**：BitNet b1.58三値重みのn-gramメモリ実験は概念実証だ。192のルーティングエキスパートへの同様の量子化適用でメモリフットプリントを大幅に削減しつつ精度を維持できる可能性がある（MoEエキスパートはその疎な性質上、量子化に適している）。

## エッジ・オンデバイスへの示唆

Metis-1.6は主にオンデバイスモデルとして設計されていない—MI300Aアクセラレータで大規模学習された。しかしいくつかの設計選択は効率的な展開に直接の含意を持つ。

**エッジに有利な点**：
- **選択的KVキャッシュ**：Logosでは20層中3層のみがKVキャッシュを保持。128Kコンテキストでも、メモリ帯域幅のボトルネックが通常のトランスフォーマーより大幅に小さい。
- **低アクティブパラメータ数**：Praxisはパス当たり0.46Bをアクティブ化。Dense 1Bモデルと同程度の計算コストで、2.94B分のルーティング可能な知識を持つ。フラッシュストレージに全重みを保持しつつSRAM/HBMは限られているデバイスに有利なトレードオフ。
- **Mamba-2の優位性**：Mamba-2レイヤーは推論時のトークンごとの状態サイズがO(1)（アテンションのKVキャッシュはO(n)）。ストリーミングや長セッションのオンデバイス推論で根本的な優位がある。
- **位置エンコーディングなし**：実装がシンプルで、適応時に調整すべきハイパーパラメータが一つ少ない。

**エッジで困難な点**：
- 2パス設計はシーケンシャルな深度を倍増させ、アクティブFLOPが同じでも遅延を増加させる。レイテンシが厳しいリアルタイムアプリケーションではこれが重要になる。
- BF16でのフルLogosチェックポイントは20.80GB—一般的なモバイルデバイスのRAMには収まらない。Praxisの6.16GBはハイエンドデバイスでギリギリ。
- MoEルーティングは疎なディスパッチを必要とし、Dense行列演算向けに設計された固定機能NPUでは効率的な実装が困難。

Praxisのサイズクラス（2.94B全体、0.46Bアクティブ）がより即座に展開可能だ。INT4/INT8量子化で、ハイエンドモバイルハードウェアでの動作が現実的になる。Mamba重視のハイブリッド・潜在MoE・位置エンコーディングなしという設計選択は、たとえそれが明示的な目標でなくとも、この可能性を念頭に置いているように見える。
