Title: Daedalus-150M：CPU推論に特化して設計されたConvolution-Attentionハイブリッドモデル
Date: 2026-08-25
Category: AI/ML
Tags: SLM, AI, 論文解説
Summary: Daedalus-150MはCPUシングルユーザー推論を最初から設計目標に据えた150Mパラメータのハイブリッドモデルで、6つのAttentionブロックと12個のConvolutionブロックにより、等パラメータのAll-Attentionモデル比で2048トークン文脈において1.76倍の高速デコードを実現する。

## なぜこの研究が重要か

多くのSLMは大規模モデルと同じアーキテクチャで構築され、後からCPU向けに圧縮される。Daedalus-150Mはその逆を行う。著者たちは**まず展開先を固定**した——1ユーザー、1トークンずつ、4ビット量子化重み、通常のCPU——そのうえでアーキテクチャを選択した。

CPUはGPUとは根本的に異なる3つの制約を課す。

1. **バッチ処理がない。** 各トークン生成のたびにモデルの全重みをメモリ階層から読み込む必要がある。スループットは演算量ではなく「トークンあたりのバイト読み込み量」に支配される。
2. **メモリ帯域がボトルネック。** 現代のCPUは演算能力よりはるかに少ないバイトしか供給できない。少ないバイトで多くの演算を行うアーキテクチャが勝つ。
3. **KVキャッシュは増え続ける負債。** 標準的なAll-Attentionデコーダでは、各トークン生成のたびに全レイヤーで全過去トークンのKVを再読み込みする。このコストは文脈長に比例し、毎トークン支払われる。

Daedalusが引くのは3つ目のレバーだ。ほとんどのレイヤーが定サイズの再帰状態を使うなら、デコードコストは文脈長に対してほぼ一定になる——ユーザーがレイテンシを感じる場面、すなわち長い会話や長文書において優位性が最大化する。

## 技術的なアプローチ

### アーキテクチャ：18ブロック、6 Attention、12 Convolution

Daedalus-150Mは160.49Mパラメータ、18ブロック構成（`d_model = 768`、FFN内部次元2048、語彙49,152、文脈長2048）。ブロックのレイアウトは：

```
C C C C A C C A C A C A C A C C A C
```

AはAttention（インデックス4, 7, 9, 11, 13, 16）、CはShort Convolution。6つのAttentionブロックが長距離検索能力を担い、12のConvolutionブロックが定コストの再帰を担う。

### Short-Convolutionブロックの設計

各Convolutionブロックの計算：

$$B, C, x = \text{in\_proj}(u) \quad \text{（3分割）}$$

$$y = \text{depthwise\_conv1d}(B \odot x)$$

$$\text{out} = \text{out\_proj}(C \odot y)$$

カーネル長$L=3$、Depthwise（チャンネルごとに独立したフィルタ）。この再帰的状態は文脈長によらず常に$L-1=2$タイムステップ分の幅しか持たない。ゲーティング項$B$と$C$が固定カーネル単体では持てない入力依存の振る舞いを与える。

**核心：** Convolutionブロックを通じたデコードは、トークン2000でもトークン2と同じコストがかかる。Attentionブロックはそうではない。

### なぜちょうど6つのAttentionレイヤーか

純粋なConvolutionは精密な長距離検索——Attentionが唯一提供する操作——を失う。6つのAttentionレイヤーを深さ全体に分散配置することで、様々な表現レベルに検索能力を分配する。この比率（6/18、33%がAttention）はバッチサイズ1のCPUデコードに対するメモリトラフィック解析から導出され、事前登録した実験で検証された。

### 補助的アーキテクチャ選択

**Grouped-Query Attention (GQA):** 12個のクエリヘッドに対して4個のKVヘッド。6つのAttentionレイヤーのキャッシュをさらに3分の1に削減。動機はトークンあたりのバイト数削減。

**埋め込みの共有（Tied Embeddings）:** 埋め込み行列（49,152×768）はモデルの23%を占める37.7Mパラメータ。入力と出力の射影を共有することで、ファイルサイズとメモリ転送量の両方から重複コピーを排除。

**狭いFFN:** 内部次元を従来の4×でなく2.67×（2048）に設定。パラメータをAttentionと深さ方向にシフトし、帯域幅コストの高い大テンソルを減らす。

### コストモデル：アーキテクチャが何を提供するか

バッチサイズ1での1トークン生成あたりの読み込みバイト数：

$$M(t) = W + \underbrace{2 \cdot L_A \cdot h_{kv} \cdot d_h \cdot b}_{\kappa} \cdot t$$

$W$は量子化重みのバイト数、$t$は文脈深さ。

- Daedalus: $\kappa_{\text{hyb}} = 6{,}144$ B/トークン
- Dense twin (全Attention): $\kappa_{\text{dense}} = 12{,}288$ B/トークン

理論予測では2048トークン時1.17倍の高速化を示すが、実測は1.76倍。差分はAttentionのキャッシュ読み込みがL3キャッシュ容量を超えたときのレイテンシ律速（softmax計算の依存性）と、Daedalusが18対24のブロック数である点（固定コストを25%少なく支払う）に帰因する。

### 学習

- **データ:** 10ソース英語コーパス計16.93Bユニークトークンから59.9Bトークン（約3.5エポック）、ソースあたり最大4エポック上限
- **最適化:** 2次元重み行列にMuon、埋め込み・ノルム・バイアスにAdamW
- **学習率スケジュール:** ウォームアップ→安定→ゼロへの線形減衰（コサインでなく、ゼロへの完全減衰が最もサンプル効率が高い）

## 先行研究との比較

論文は5タスクベンチマークのバー（**42.20**、比較対象で最強のMobileLLM-125M等）を学習開始前に事前登録。全ての比較モデルは同一ハーネスで再スコア。

| モデル | 学習トークン数 | 5タスク平均 |
|---|---|---|
| GPT-2 124M | ~300B | ~42.0 |
| Pythia-160M | ~300B | ~42.1 |
| MobileLLM-125M | 1T | ~42.2 |
| **Daedalus-150M（フル）** | **59.9B** | **47.31** |

3〜6倍少ないデータでバーを5.11ポイント上回る。2Tトークン学習ペアは3.9ポイント上回るが、それはデコード速度との意図的なトレードオフとして著者が事前に承諾したもの。

アブレーション実験（ハイブリッドvs. Denseツイン、両者5Bトークン学習）では、ハイブリッドが検証ビット/バイトで0.81%上回り、ダウンストリームタスクではタイ——品質差は小さく速度差は大きいことを確認。

## 実験結果の読み方

**CPUデコード速度**（4ビット重み、8スレッド、文脈深さ$t$からの128トークン生成）：

| 文脈深さ | ハイブリッドvs. Denseツイン | ハイブリッドvs. 外部135Mモデル |
|---|---|---|
| 0トークン | ~1.0× | ~1.0× |
| 512トークン | 増大中 | 増大中 |
| 2048トークン | **1.76×** | **2.08×** |

**形状こそが命題だ。** 空文脈では優位性がほぼゼロ——優位性はキャッシュを持たないことから生まれ、空文脈にはキャッシュが存在しない。文脈が深くなるにつれて単調増大する。

**ファイルサイズ:** 95.56 MiB（Q4_0）vs. Denseツイン101.62 MiB（6.3%小さい）。

**メモリフットプリント:** 2048トークン文脈でモデル+KVキャッシュ（~12.6 MB）の合計が128 MB未満——アプリと同居できるサイズ。

## アルゴリズムの重要部分の解説

Convolutionブロックの3段階演算を丁寧に見ていこう：

**ステップ1: 入力射影の3分割**
$$B, C, x = \text{in\_proj}(u)$$

入力$u$を線形変換で3つのテンソルに分割する。$B$は入力ゲート、$C$は出力ゲート、$x$は畳み込み対象のコンテンツ信号。このゲート構造により、畳み込みが「何に注目するか」を文脈依存で制御できる。固定カーネルだけでは不可能な適応性を与えるのがこの仕組みの本質。

**ステップ2: ゲートされた深さ方向畳み込み**
$$y = \text{depthwise\_conv1d}(B \odot x)$$

アダマール積$B \odot x$で入力をゲートしたあと、深さ方向1D畳み込みを適用。Depthwiseとはチャンネルが互いに独立して処理されること——カーネル長3なので、各チャンネルには直前2タイムステップの$(B \odot x)$の値しか必要ない。これが**定サイズ状態**の正体だ。文脈長1000でも5000でも、各チャンネルは2スカラーのバッファしか持たない。

**ステップ3: 出力ゲーティング**
$$\text{out} = \text{out\_proj}(C \odot y)$$

畳み込み結果$y$を出力ゲート$C$で選択的に通過させ、最終的な線形変換を適用。これにより不要な特徴を抑制し、残差ストリームへの寄与を精製する。

**AttentionのKVキャッシュとの対比：**
- Attentionブロックのデコードには「全過去トークンのKVベクトル」が必要 → 文脈長$t$に線形のメモリ
- Convolutionブロックは「直前2タイムステップのゲートコンテンツ」だけを必要 → 定数メモリ

$M(t) = W + \kappa \cdot t$の式が示すように、長文脈ではKVキャッシュ読み込み項$\kappa \cdot t$がコストを支配する。Daedalusはこの項の係数（$\kappa$）を半分に削減し、かつ発生するレイヤー数も減らすことで、理論予測を超える速度向上を達成した。

## 限界と課題

論文は失敗も透明に報告している：

- **死んだチャンネル:** 短Convolutionチャンネルの約47.9%が出力に何も寄与しない（~13.6Mパラメータの無駄）。構造的プルーニングは推論ランタイムの形状チェックで阻まれた。
- **量子化対応学習（QAT）の失敗:** QATは最初のステップで非有限損失を生じて無効化。リリースモデルには後学習量子化で約6%のパープレキシティペナルティが残る。
- **語彙サイズの過大:** 49,152トークン（最適は24〜32k）は廃止された蒸留計画の名残。埋め込み表が~13Mパラメータを無駄にしている。
- **単一シード、英語のみ:** 信頼区間なし。0.81%のアブレーションマージンは統計的に有意とは言えない。
- **学習データ混合のドリフト:** エポック上限と学習再起動による実際の混合比の目標からの乖離。

## 今後の展望

**著者が示すFuture Work：**
- QATの失敗を診断し、完成チェックポイントから実施
- 初期化段階での死んだチャンネルへの対処
- 設計済みだが未実施の深さアブレーション（18×768 vs. 24×640）
- マルチシードでのアブレーション再現
- 検索感度評価で最小必要Attention比を特定

**派生的研究の可能性：**
- **適応的Attention比率:** 現在の6/18比は解析的に決定されたもの。微分可能アーキテクチャ探索でタスクファミリーごとの最適比率を学習することで、さらなる改善が期待できる。
- **Convolutionカーネルの最適化:** 測定速度は帯域幅モデルを超えており、専用CPUカーネルのチューニングで更なる向上余地がある。
- **より長い文脈での学習:** 2048トークンでの学習だが、帯域幅モデルは文脈長が延びるほど優位性が増大することを予測する。4096+での検証が必要。
- **投機的デコードとの組み合わせ:** 定サイズ状態のConvolutionブロックは効率的なドラフトモデルとして機能できる可能性があり、投機的デコードとの組み合わせは高い相性が期待できる。

## エッジ・オンデバイスへの示唆

Daedalus-150Mは「まず展開制約を定義し、アーキテクチャをそれに合わせる」という方法論の実証例として重要だ：

- **95.56 MiB Q4_0 + ~12.6 MB KVキャッシュ < 128 MB** — 現代スマートフォンでアプリと同居できるサイズ
- **1.76〜2.08倍の高速デコード**（現実的な会話長で）は実際にユーザーが体感できる応答速度の改善
- **より低いコア数でのスレッド飽和** はモデルが電話のCPUコアを独占する可能性が低いことを意味する
- **stock llama.cppバイナリとの互換性** — カスタムオペレーター不要で即座に展開可能

より広い教訓として：シングルユーザーCPU展開では、Attentionレイヤーの3分の2をShort Convolutionに置き換えることは「品質面では無料」であり、レイテンシ面で大きな配当をもたらす。このアーキテクチャ原理はこの特定のモデルサイズを超えて一般化する可能性がある。
